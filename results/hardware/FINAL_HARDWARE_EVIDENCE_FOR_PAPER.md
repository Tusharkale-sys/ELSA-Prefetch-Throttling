# ELSA Final Hardware Evidence for Paper

## Scope

This package closes the hardware-validation evidence for the exact frozen ELSA controller RTL. No post-result RTL redesign, pipelining, arithmetic change, precision change, Q-table change, target change, or result-driven retuning was performed.

The hardware evidence covers controller RTL only. It does not constitute a complete RTL implementation of sBerti or a full processor, so a percentage area overhead relative to the complete prefetcher or processor is not available.

## Level A — RTL correctness and generic synthesis

The ELSA controller was implemented as synthesizable SystemVerilog and validated against an independently implemented software reference.

A 100,000-epoch stress comparison between the software double-precision implementation and the Q24 reference produced zero state, action, and degree mismatches. The maximum observed Q-value error was approximately 1.61e-7.

A 256-epoch RTL replay, covering 1024 accesses per epoch, produced zero trajectory mismatches against the Q24 reference and was bit-exact for the tested trajectory.

Generic Yosys synthesis completed successfully. The generic synthesized representation contained 45,105 cells, including 6,404 synthesized sequential bits/cells and 38,701 combinational cells. No residual divider, modulo, multiplier, or memory structures remained after synthesis.

The synthesizable RTL controller contains 6,417 bits of online state, corresponding to 803 bytes when rounded to whole bytes. This is narrower in scope than the earlier 822-byte software/controller-support estimate and the two values must not be presented as identical quantities.

## Level B — Named FPGA implementation

The exact frozen RTL was synthesized, placed, and routed for a Lattice ECP5 LFE5U-85F device, CABGA381 package, speed grade 6.

The implementation successfully placed and routed but failed the preregistered 100 MHz timing target.

Post-route estimated maximum frequency was approximately 3.2 MHz.

Reported utilization was approximately:

- combinational resources: 16,258 / 83,640 (19.44%)
- flip-flops: 6,404 (7.66%)
- DSP blocks: 10 / 156 (6.41%)
- block RAM: 0

The critical path was dominated by the monolithic SARSA/Q-value update arithmetic. This result demonstrates implementability on the named FPGA target, but also demonstrates that the present single-cycle arithmetic organization is not timing-efficient.

No post-result pipelining or multicycle redesign was performed.

## Level C — Nangate45 standard-cell synthesis and pre-layout STA

The same frozen RTL was mapped with Yosys/ABC using the Nangate45 FreePDK45 typical Liberty library.

The mapped design contains:

- 30,409 standard-cell instances
- 63,041.734 Liberty-reported total cell-area units

The area quantity above is a Liberty cell-area sum. It is not physical die area, placed area, routed area, or fabricated-silicon area.

OpenSTA 3.1.0 did not accept `wire signed` declarations emitted in the Yosys gate-level Verilog. A timing-only compatibility copy was therefore generated by removing exactly 33 `signed` declaration annotations. The authoritative mapped netlist was left unchanged.

The compatibility copy was verified against the authoritative mapped design. Top-level port connectivity, cell-instance dictionary, cell types, cell parameters, cell-pin directions, cell-pin connectivity, and referenced-bit sets were identical. The 33 affected signed nets retained identical bit connectivity. Extra netnames in the authoritative parse were Yosys-generated `$indirect$` aliases and did not alter the gate graph.

Pre-layout STA used:

- Nangate45 typical Liberty corner
- 10.0 ns clock period
- 100 MHz frozen target
- ideal clock
- no extracted parasitics
- no input/output delay constraints

The valid timing result was:

- worst setup slack: -16.489399 ns
- total negative slack: -30,803.826172 ns
- derived effective critical period: 26.489399 ns
- estimated pre-layout Fmax: 37.750951 MHz
- frozen 100 MHz target: NOT MET

OpenSTA returned a nonzero process code only after the timing reports had completed because this build did not support the auxiliary `report_design_area` Tcl command. The reported slack and TNS precede that command failure and constitute the frozen C2 timing result. OpenSTA was not rerun after that valid timing result.

One derived-field parser artifact exists in the frozen C2 text: `REPORTED_CRITICAL_PATH_DATA_ARRIVAL_NS=-26.447119` was extracted from the subtraction line in the timing report. The actual critical-path arrival reported earlier in the same OpenSTA path is +26.447119 ns. This does not affect worst slack, TNS, effective critical period, estimated Fmax, or the 100 MHz pass/fail result.

## Paper-safe interpretation

The hardware evidence supports the statement that the exact ELSA controller is synthesizable and can be mapped to both an FPGA fabric and a standard-cell library.

The evidence does not support a claim that the current monolithic implementation operates at 100 MHz. The ECP5 implementation reached approximately 3.2 MHz post-route, while Nangate45 pre-layout STA indicated approximately 37.75 MHz under ideal-clock, zero-parasitic assumptions.

The results therefore expose timing optimization as an implementation limitation rather than hiding it. Because the controller updates only at SARSA epoch boundaries in the evaluated architecture, pipelining or multicycle implementation is a plausible future direction, but feasibility and final frequency are not established by the present experiments.

The hardware study does not provide:

- ASIC post-route timing
- extracted parasitic timing
- physical die/core area
- dynamic or leakage power
- energy per access
- fabricated silicon measurements
- full-sBerti area-overhead percentage

Accordingly, the paper must not describe ELSA as energy-efficient on the basis of these hardware experiments.
